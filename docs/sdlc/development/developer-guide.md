<!-- sdlc:auto:start overview -->
TimeTrack Pro is a planned time and labour management web app (timesheets, approvals, leave, labour rules, reports). It was generated by the Quorq AI SDLC platform as two applications in one repository. `frontend/` is a Vite + React 19 single-page app (TypeScript, Tailwind CSS 4, React Router 7) whose screens render seeded sample data. They are not yet wired to the API. `frontend/src/lib/api.ts` provides an `apiFetch` helper as the seam for doing that. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Pydantic 2. It defaults to a local SQLite database and can point at PostgreSQL through `DATABASE_URL`. A `docker-compose.yml` provides a Postgres 16 container for that. The backend currently exposes only `GET /health`. It has no models, routers, or migrations yet, and tables are created from models at startup.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for frontend/)
- Python 3.12 with pip (the backend Dockerfile uses python:3.12-slim)
- Docker with Docker Compose (optional: only for the PostgreSQL container or building the backend image)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd frontend && npm install
2. cd backend && pip install -r requirements.txt
3. Optional, to use PostgreSQL instead of the default SQLite file (backend/app.db): run `docker compose up -d db` from the repo root, then set DATABASE_URL in the backend environment to point at it (the compose service uses user/password/db `app` on port 5432; the installed driver is psycopg 3)
4. cd backend && uvicorn app.main:app --reload
5. In a second terminal: cd frontend && npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend imports use the `@/` alias for `frontend/src`, configured in both vite.config.ts and tsconfig.json.
- Component tests (*.test/*.spec.ts(x)) live inside src/ beside the components they cover. Playwright specs live in frontend/e2e and are excluded from Vitest.
- TypeScript runs in `strict` mode, but `noImplicitAny` and `strictNullChecks` are disabled.
- Formatting uses Prettier (.prettierrc) and ESLint 9 flat config with eslint-config-prettier, React Hooks and React Refresh plugins. Styling uses Tailwind CSS 4 via @tailwindcss/vite.
- Screens render seeded sample data. Real API calls should go through `apiFetch` in src/lib/api.ts. It reads `VITE_API_BASE_URL` (default http://localhost:8000) and sends a bearer token from `setSessionToken`/localStorage, falling back to `VITE_API_SECRET_KEY`.
- Backend models inherit `Base` from app/database.py and must be defined in app/models.py, which main.py imports so tables register before `create_all`.
- Database sessions come from the `get_db` dependency (one session per request). `DATABASE_URL` defaults to `sqlite:///./app.db`.
- Routers go in app/routers/, one per architecture component. Unimplemented routes return the typed `StubResponse` schema instead of raising.
- CORS origins come from the comma-separated `ALLOWED_ORIGINS` env var. When it is unset, they default to http://localhost:5173 and http://127.0.0.1:5173.
- There are no migrations. Schema is created at startup with `Base.metadata.create_all`, and the code notes that Alembic should replace this before storing real data.
- Backend linting and formatting use Ruff (ruff.toml).

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The frontend fails to resolve `@/App` on dev or build. | main.tsx imports `@/App`, and frontend/README.md describes `src/App.tsx` and `src/screens/`, but neither appears in this repository's file tree. Make sure `frontend/src/App.tsx` exists; the frontend cannot start without it. |
| `npm run test:e2e` fails to start the API server. | Playwright launches the backend with `backend/.venv/bin/python`. Create a virtual environment at backend/.venv and install backend/requirements.txt into it, or set E2E_BASE_URL to test against an already running app. |
| Playwright reports that the browser executable is missing. | Run `cd frontend && npm run test:e2e:install` first. |
| The browser blocks API calls with a CORS error. | Without ALLOWED_ORIGINS, the backend only allows http://localhost:5173 and http://127.0.0.1:5173. Use the Vite dev server on that port, or set ALLOWED_ORIGINS (comma separated) to your frontend origin. |
| `pytest` cannot import `app`. | Run pytest from the backend/ directory so pytest.ini (pythonpath = .) is picked up. |
| The build succeeds but the typecheck fails. | `npm run build` does not typecheck. Run `npm run typecheck` and fix the reported errors, which are typically untyped `useState({})` values. |
| The backend fails on startup when connecting to the database. | The connection is opened at startup, not import. If DATABASE_URL points at Postgres, start it with `docker compose up -d db` and wait for its healthcheck to pass, or unset DATABASE_URL to use the default SQLite file. |
| Model changes don't appear in an existing SQLite database. | `create_all` only creates missing tables and never alters existing ones. Delete backend/app.db during development, or add migrations. |
<!-- sdlc:auto:end troubleshooting -->
